### Prompt

> The domain classes carry the rules of the system: blood type compatibility, whether a pack has expired, and which state changes are allowed. Write unit tests for those rules. Consider the following requirements:
> plain JUnit 5 only. the tests construct domain objects directly and call their methods;
> test BloodType.canDonateTo for every ordered pair of blood types, so that all 64 combinations are checked.
> test each state transition method on BloodPack twice: once from a state the statechart allows, and once from a state it does not.
> test isExpired() and canBeIssued() on both sides of their conditions
> test isCompatibleWith(Patient) for a compatible and an incompatible pairing

### Decisions made by the generator, accepted

- A private `record Antigens(boolean hasA, boolean hasB, boolean hasRh)` inside the test, to
  keep the antigen profile of each type as data rather than as logic.
- A `default` branch throwing `IllegalArgumentException`, so adding a blood type without
  updating the test fails, instead of quietly returning a wrong answer.
- A `createPack` helper in `BloodPackTest` building the `Donor → Donation → BloodPack` chain,
  which the constructors require.
- One allowed and one disallowed state per transition method, rather than every
  disallowed state for every method.

### What the tests establish

- Compatibility: all 64 ordered pairs of blood types agree with the antigen rule.
- State transitions: each of the five transition methods succeeds from a state the
  statechart permits and is rejected from one it does not, so the statechart is enforced by
  the code, not only drawn.
- Expiry: `isExpired()` and `canBeIssued()` behave correctly on both sides of their
  conditions.
