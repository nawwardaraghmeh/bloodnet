## P06 — Services → REST controllers

**Generator:** DeepSeek
**Accepted output:** `prompts-output/P06-output.md`

### Prompt

> Write the layer of controllers that exposes these services as HTTP endpoints using Jakarta REST, consider the following requirements:
> there is one controller per service, exposing the use cases of that service;
> controllers are associated to services using CDI dependency injection;
> a controller receives the request, calls one service method, and returns its result. No business logic and no database access in the controller;
> requests and responses are JSON.


### Issues detected and asked to modify

| # | Issue | Correction requested |
|---|---|---|
| 1 | Omitted class-level `@Path` annotations on REST controllers, causing JAX-RS to ignore the classes entirely and return `404 Not Found` for all endpoints. | Add class-level `@Path` annotations (`/collection`, `/inventory`, `/transfusion`) to register each controller while keeping method-level paths unchanged. |
| 2 | Declared `@Consumes(APPLICATION_JSON)` at the class level, causing body-less URL requests (like `placePackInStorage`) to fail with a `415 Unsupported Media Type` error. | Move `@Consumes` down to the methods that actually take a request body. |

### Decisions made by the generator, accepted

- **Direct return types rather than `Response`**, letting JAX-RS supply `200 OK` with a JSON
  body and `204 No Content` for `void` methods. No `201 Created` with a `Location` header,
  which would have required the controller to know the URI of what it created.
- **No exception mappers and no bean validation.** Service exceptions propagate to the default
  JAX-RS handling, which returns 500 with a stack trace. Recorded as the reason for the next
  step.
- **`DonationResponse` carries `List<String> packCodes`** rather than nested pack objects,
  to keep the response small and non-recursive.
