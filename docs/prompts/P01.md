## P01 — Conceptual model → domain classes

**Model used:** `models/conceptual-model.jpg`

### Prompt

> Attached (models/conceptual-model.png) is a UML conceptual class diagram for a blood
> donation tracking system. Generate the Java domain classes for this model, with the
> following requirements: plain Java only: no annotations, no framework imports. use
> enums where an attribute has a fixed set of values / private fields, a public
> constructor for creating new objects, getters, and setters only where a value can
> legitimately change.
> Structure only: no business rules or validation yet

A standing instruction was added at this point and kept for every later prompt:

> At the end of your response, list every decision you made that was not specified in the
> diagram or in these instructions.

This makes the generator declare its own assumptions, instead of leaving them to be found
by reading the code line by line.

### Issues detected and asked to modify

| # | Issue | Correction requested |
|---|---|---|
| 1 | `Issue.outcome` used plain text (`String`) instead of a fixed list of allowed choices. | Replace plain text with a predefined choice list (`enum`: `TRANSFUSED`, `RETURNED`, `WASTED`). |
| 2 | Object links worked in only one direction (e.g., a `Donation` knew its `Donor`, but `donor.getDonations()` stayed empty). | Link both ends of the relationship inside constructors so both objects know about each other from the start. |
| 3 | List methods handed out the real internal list, letting outside code bypass class rules to add or remove items directly. | Return a read-only view of the list so outside code can view items without modifying the internal list. |
| 4 | Boolean methods used non-standard names like `hasRedCells()`, which prevents database (JPA) and JSON tools from auto-detecting properties. | Rename fields to `redCells`, `plasma`, `platelets` and use standard getter names like `isRedCells()`. |
| 5 | Setter methods allowed changing permanent data (like unique ID codes and event timestamps) after an object was created. | Remove setter methods for fixed IDs (`fiscalCode`, `healthNum`, `packCode`, `code`) and historical timestamps (`collectedAt`, `producedAt`, `issuedAt`). |

- All five corrections were applied in the accepted output. Setters remain only on
`screeningStatus`, `state`, `storageLocation` and `outcome`.

- Mechanical changes made: a package it.unifi.swam.domain; declaration was added to each of the ten files. The prompt did not ask for one. No other edit was made to the generated code.

### Decisions made by the generator, accepted

- The link between `StorageLocation` and `BloodPack` was made readable from both ends.
  `setStorageLocation` keeps the two sides in step and detaches the pack from its previous
  location.
- Two-way links are kept consistent through package-private `addX(...)` methods on the
  parent class, so no public method can corrupt an association. This forces all ten classes
  into a single package.
- `screeningStatus` is passed to the `Donation` constructor rather than starting at
  `PENDING`.
- `Issue.outcome` starts as `null`, since the outcome is not known at the moment blood is
  issued.
